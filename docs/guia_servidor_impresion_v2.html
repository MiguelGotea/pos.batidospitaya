Guía Completa de Instalación — Servidor de Impresión Local Node.js

Esta guía paso a paso te permitirá instalar, configurar y replicar el servidor de impresión para la ticketera Epson TM-T20II (o cualquier ticketera térmica USB) en cualquier computadora con Windows en la empresa desde cero.

PASO 0 — Instalar Node.js (Si la PC no lo tiene)

Para ejecutar el servidor, la computadora debe tener Node.js instalado.

  1. Descarga la versión LTS (Recomendada para la mayoría) desde la página oficial: nodejs.org.
  2. Ejecuta el instalador descargado. Sigue el asistente pulsando Siguiente → Siguiente → Instalar → Finalizar (deja marcadas las opciones por defecto).
  3. Abre una terminal (CMD o PowerShell) y verifica que se haya instalado correctamente escribiendo:
    node -v
npm -v
    (Debería mostrarte los números de versión de Node y npm sin errores).

PASO 1 — Compartir la Impresora en Windows (Crucial)

Como usaremos un puerto de Windows Spooler sin dependencias nativas de compilación (C++), el sistema necesita que la impresora esté compartida en la red local.

  1. Abre el Panel de Control > Dispositivos e impresoras (o busca "Impresoras y escáneres" en la configuración de Windows).
  2. Haz clic derecho sobre tu impresora Epson y selecciona Propiedades de la impresora (no "Propiedades").
  3. Ve a la pestaña Compartir.
  4. Marca la casilla "Compartir esta impresora".
  5. En el nombre del recurso compartido escribe exactamente:
    Impresora TM Tienda
  6. Haz clic en Aplicar y Aceptar.

PASO 2 — Crear la Carpeta y Preparar el Proyecto

Abre la terminal (CMD o PowerShell) y ejecuta los siguientes comandos para crear la carpeta del servidor e instalar las librerías necesarias:

# 1. Crear e ingresar a la carpeta del servidor
mkdir C:\ServidorImpresora
cd C:\ServidorImpresora

# 2. Inicializar el proyecto Node.js
npm init -y

# 3. Instalar dependencias necesarias
npm install express node-thermal-printer cors
NOTE: Al ejecutar `npm init -y` es totalmente normal y esperado que veas una línea que dice `"test": "echo \"Error: no test specified\" && exit 1"`. No te preocupes, esto **NO** es un error real del sistema. Simplemente es una plantilla por defecto que Node.js genera para scripts de testing que no usaremos. Puedes continuar al Paso 3 con total tranquilidad.
NOTE: Al ejecutar `npm install`, verás mensajes como `X packages are looking for funding` y al final `found 0 vulnerabilities`. Ambos son **normales y esperados**: - **"looking for funding"** → Solo es un aviso de que los autores de algunas librerías aceptan donaciones voluntarias. No tienes que hacer nada. - **"found 0 vulnerabilities"** → ✅ Significa que la instalación fue exitosa y sin problemas de seguridad. Puedes continuar.

PASO 3 — Crear los Archivos del Servidor

Dentro de C:\ServidorImpresora\, crea los siguientes archivos con sus respectivos códigos:

1. C:\ServidorImpresora\package.json

Asegúrate de que tu package.json tenga esta estructura (puedes sobrescribirlo):

  "version": "1.0.0",
  "description": "Servidor de impresion local para Batidos Pitaya",
  "main": "servidor.js",

2. C:\ServidorImpresora\servidor.js

Este archivo contiene la lógica del servidor de Express y el controlador de impresión personalizado para Windows:

const express = require('express');
const cors = require('cors');
const path = require('path');
const fs = require('fs');
const { exec } = require('child_process');
const { ThermalPrinter, PrinterTypes } = require('node-thermal-printer');

const app = express();
app.use((req, res, next) => {
  res.setHeader('Access-Control-Allow-Private-Network', 'true');
  if (req.method === 'OPTIONS') {
    res.setHeader('Access-Control-Allow-Headers', 'Content-Type, Access-Control-Allow-Private-Network');
  }
  next();
});
app.use(cors());
app.use(express.json());

// Nombre del recurso compartido en Windows tal como lo configuraste en el Paso 1
const NOMBRE_IMPRESORA = 'Impresora TM Tienda';

// Interfaz de impresión personalizada para Windows Spooler
// Evita instalar drivers nativos C++ que fallan al compilar en Windows
const windowsSpoolerInterface = {
  isPrinterConnected: async () => {
    return true; // Asumimos conectada; el spooler de Windows se encargará de encolarla
  },
  execute: async (buffer) => {
    const tempFile = path.join(__dirname, `print_job_${Date.now()}.bin`);
    
    // 1. Guardar el buffer ESC/POS en un archivo temporal
    await fs.promises.writeFile(tempFile, buffer);
    
    return new Promise((resolve, reject) => {
      // Ruta UNC para mandar al spooler compartido localmente
      const printerPath = `\\\\localhost\\${NOMBRE_IMPRESORA}`;
      
      // 2. Usar copy /b para copiar los bytes directamente a la cola de la impresora sin alterarlos
      exec(`copy /b "${tempFile}" "${printerPath}"`, (err, stdout, stderr) => {
        // Borrar siempre el archivo temporal inmediatamente después
        try { fs.unlinkSync(tempFile); } catch (e) {}
        
        if (err) {
          console.error("Error de impresión en Spooler:", err);
          reject(new Error(`No se pudo enviar a la impresora. ¿Está compartida como "${NOMBRE_IMPRESORA}"?`));
        } else {
          console.log("Trabajo de impresión enviado correctamente a la cola.");
          resolve('Printed successfully');
        }
      });
    });
  }
};

// Servir la carpeta de control estática
app.use(express.static(path.join(__dirname, 'public')));

// Estado del Servidor
app.get('/estado', (req, res) => {
  res.json({ 
    estado: 'Servidor de impresión activo', 
    impresora: NOMBRE_IMPRESORA 
  });
});

// Endpoint para imprimir
app.post('/imprimir', async (req, res) => {
  const { lineas } = req.body;

  if (!lineas || !Array.isArray(lineas)) {
    return res.status(400).json({ error: 'Se esperaba un array de líneas: { lineas: ["texto1", "texto2"] }' });
  }

  try {
    const printer = new ThermalPrinter({
      type: PrinterTypes.EPSON,
      interface: windowsSpoolerInterface, // Usamos nuestra interfaz robusta sin módulos nativos
      characterSet: 'SLOVENIA',
      removeSpecialCharacters: false,
      lineCharacter: '-',
    });

    printer.alignCenter();
    printer.println("================================");
    printer.println("       BATIDOS PITAYA");
    printer.println("================================");
    printer.alignLeft();

    for (const linea of lineas) {
      printer.println(linea);
    }

    printer.alignCenter();
    printer.println("================================");
    printer.println("  Gracias por preferirnos!");
    printer.println("\n\n");
    printer.cut();

    await printer.execute();
    res.json({ ok: true, mensaje: 'Ticket enviado a la impresora correctamente' });
  } catch (err) {
    console.error('Error procesando la impresión:', err);
    res.status(500).json({ error: err.message });
  }
});

const PUERTO = 3000;
app.listen(PUERTO, () => {
  console.log(`Servidor de impresión corriendo localmente en el puerto ${PUERTO}`);
  console.log(`Prueba en tu navegador: http://localhost:${PUERTO}/`);
});

  // ── Config helpers ──────────────────────────────────────────
  const getIP   = () => document.getElementById('cfg_ip').value.trim() || '192.168.0.67';
  const getPort = () => document.getElementById('cfg_port').value.trim() || '3000';
  const baseUrl = () => `http://${getIP()}:${getPort()}`;

  // ── Log helper ──────────────────────────────────────────────
  function log(msg, type = '') {
    const box = document.getElementById('log');
    const ts  = new Date().toLocaleTimeString('es', { hour12: false });
    const div = document.createElement('div');
    div.className = `log-entry ${type}`;
    div.textContent = `[${ts}] ${msg}`;
    box.appendChild(div);
    box.scrollTop = box.scrollHeight;
  }

  // ── Status check ────────────────────────────────────────────
  async function checkStatus() {
    const dot  = document.getElementById('status-dot');
    const text = document.getElementById('status-text');

    dot.className = 'status-dot';
    text.textContent = 'Verificando...';
    log(`Conectando a ${baseUrl()}/estado ...`, 'inf');

    try {
      const res  = await fetch(`${baseUrl()}/estado`, { signal: AbortSignal.timeout(4000) });
      const data = await res.json();

      dot.className = 'status-dot online';
      text.innerHTML = `Servidor activo · <span id="printer-name">${data.impresora || '?'}</span>`;
      log(`✅ Servidor OK. Impresora: "${data.impresora}"`, 'ok');
    } catch (err) {
      dot.className = 'status-dot offline';
      text.textContent = 'Servidor desconectado';
      log(`❌ Sin conexión al servidor: ${err.message}`, 'err');
    }
  }

  // ── Fetch de impresión ──────────────────────────────────────
  async function enviar(lineas) {
    log(`Enviando ${lineas.length} línea(s) a imprimir...`, 'inf');
    try {
      const res  = await fetch(`${baseUrl()}/imprimir`, {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({ lineas }),
        signal: AbortSignal.timeout(8000)
      });
      const data = await res.json();
      if (data.ok) {
        log('✅ ¡Ticket enviado correctamente a la impresora!', 'ok');
        return true;
      } else {
        log(`❌ Error del servidor: ${data.error}`, 'err');
        return false;
      }
    } catch (err) {
      log(`❌ Error de conexión: ${err.message}`, 'err');
      return false;
    }
  }

  function calcDias(ini, fin) {
    if (!ini || !fin) return '';
    const d1 = new Date(ini + 'T00:00:00');
    const d2 = new Date(fin + 'T00:00:00');
    if (d2 < d1) return 'Rango inválido';
    const diff = Math.round((d2 - d1) / 86400000) + 1;
    return diff + (diff === 1 ? ' día' : ' días');
  }

PASO 4 — Iniciar el Servidor Manualmente (Para Probar por Primera Vez)

Antes de configurar el inicio automático, prueba que todo funciona iniciando el servidor manualmente desde el CMD. Esto también sirve para cuando quieras probar cambios rápidamente.

  1. Abre CMD (Símbolo del sistema).
  2. Escribe los siguientes comandos:
cd C:\ServidorImpresora
node servidor.js

Si todo está correcto, verás este mensaje en el CMD y la ventana debe quedar abierta mientras usas el servidor:

Servidor de impresión HTTPS corriendo localmente en el puerto 3000
Prueba en tu navegador: https://localhost:3000/estado
  1. Abre el navegador en la misma PC y entra a https://localhost:3000/ para ver el panel de pruebas.
  2. Si entrás desde otro dispositivo en la misma red (por ejemplo, tu celular), usá la IP de la PC: https://192.168.0.67:3000/
IMPORTANT: Al entrar por primera vez a la dirección `https://:3000`, el navegador mostrará una advertencia de seguridad ("La conexión no es privada") porque el certificado SSL está auto-firmado de forma local.

Debes hacer esto una sola vez en cada dispositivo (celular o PC) desde el que vayas a imprimir:

  1. Haz clic en Configuración Avanzada (o Detalles).
  2. Haz clic en Acceder a (no seguro) o Continuar.
  3. Una vez que cargue la interfaz, el navegador recordará que confías en este servidor local y los envíos de tickets desde el ERP (que es HTTPS) funcionarán de forma directa sin bloqueos de seguridad.
NOTE: El servidor solo funciona mientras esa ventana CMD esté abierta. Si la cierras, el servidor se detiene. Por eso en el **Paso 5** configuramos el inicio automático para que no sea necesario hacer esto cada vez.

PASO 5 — Inicio Automático del Servidor (Sin CMD, Para Producción)

Para que el personal de la tienda no tenga que hacer nada técnico, configura el servidor para que arranque solo al encender la PC. Elige la opción que prefieras:

Opción A — Carpeta de Inicio de Windows (La más rápida de configurar)

Crea un archivo .vbs que inicia el servidor sin mostrar ninguna ventana CMD:

Paso A.1 — Crea el archivo C:\ServidorImpresora\iniciar_servidor.vbs con este contenido:

Set WshShell = CreateObject("WScript.Shell")
WshShell.Run "cmd /c node C:\ServidorImpresora\servidor.js", 0, False

Paso A.2 — Crea un acceso directo a ese archivo .vbs:

  • Clic derecho sobre iniciar_servidor.vbs → Crear acceso directo

Paso A.3 — Copia ese acceso directo a la carpeta de inicio automático de Windows:

  • Presiona Win + R, escribe shell:startup y presiona Enter
  • Pega el acceso directo dentro de esa carpeta

Resultado: La próxima vez que el usuario inicie sesión en Windows, el servidor arrancará automáticamente en segundo plano. El personal de la tienda no verá nada, el servidor simplemente funciona.

NOTE: Con esta opción, si el servidor falla por algún error, no se reinicia solo. Para una solución más robusta, usa la Opción B o C.

Opción B — Tarea Programada de Windows (Recomendada para producción)

Más robusta que la Opción A porque puede ejecutarse antes de que el usuario inicie sesión y con permisos del sistema. Ejecuta este comando una sola vez en CMD como Administrador:

schtasks /create /tn "ServidorImpresora" /tr "\"C:\Program Files\nodejs\node.exe\" C:\ServidorImpresora\servidor.js" /sc ONSTART /ru SYSTEM /rl HIGHEST /f

Para verificar que quedó registrado:

schtasks /query /tn "ServidorImpresora"

Para iniciarlo manualmente sin reiniciar la PC:

schtasks /run /tn "ServidorImpresora"

Para detenerlo:

schtasks /end /tn "ServidorImpresora"

Para eliminarlo si ya no lo necesitas:

schtasks /delete /tn "ServidorImpresora" /f

Resultado: El servidor arranca con Windows incluso antes de que alguien inicie sesión. Si la PC está siempre encendida en la tienda, el servidor siempre estará disponible.

Opción C — NSSM: Servicio de Windows Real (La más profesional)

Convierte Node.js en un Servicio de Windows real (como el antivirus o el servicio de impresión de Windows). Se reinicia automáticamente si falla.

Paso C.1 — Descarga NSSM desde nssm.cc/download. Es un solo archivo .exe de ~300KB, no necesita instalación.

Paso C.2 — Copia nssm.exe a C:\nssm.exe (o donde prefieras).

Paso C.3 — Ejecuta estos comandos en CMD como Administrador (una sola vez):

C:\nssm.exe install ServidorImpresora "C:\Program Files\nodejs\node.exe" "C:\ServidorImpresora\servidor.js"
C:\nssm.exe set ServidorImpresora AppDirectory C:\ServidorImpresora
C:\nssm.exe set ServidorImpresora Start SERVICE_AUTO_START
C:\nssm.exe start ServidorImpresora

Para ver el estado del servicio:

C:\nssm.exe status ServidorImpresora

También lo puedes ver y controlar desde services.msc (Servicios de Windows) buscando "ServidorImpresora".

Para detenerlo:

C:\nssm.exe stop ServidorImpresora

Para desinstalarlo completamente:

C:\nssm.exe remove ServidorImpresora confirm

Resultado: El servidor funciona como un servicio del sistema. Se inicia solo al encender la PC, se reinicia solo si falla, y no depende de que ningún usuario haya iniciado sesión.

PASO 6 — Abrir el Puerto 3000 en el Firewall de Windows

Después de iniciar el servidor por primera vez, puede que Windows pregunte si permitir la conexión. Si no aparece ese aviso, o si desde el celular no puedes conectarte aunque el servidor esté corriendo, abre el puerto manualmente:

Ejecuta en CMD como Administrador:

netsh advfirewall firewall add rule name="ServidorImpresora Node" dir=in action=allow protocol=TCP localport=3000

Para verificar que la regla quedó creada:

netsh advfirewall firewall show rule name="ServidorImpresora Node"
TIP: Si en algún momento necesitas eliminar esta regla del firewall: `netsh advfirewall firewall delete rule name="ServidorImpresora Node"`

PASO 7 — Integrar con el ERP/POS (Desde el Navegador del Empleado)

7.1 — Encontrar la IP de la PC con la Impresora

En la PC donde está el servidor Node.js, abre CMD y escribe:

ipconfig

Busca la sección de tu conexión activa (WiFi o Ethernet) y anota el valor de "Dirección IPv4". Se verá algo así:

Dirección IPv4. . . . . . . . . . . : 192.168.1.5

Esa es la IP que necesitas para el siguiente paso.

7.2 — ¿Qué es una IP fija y cuándo la necesito?

Por defecto, el router asigna una IP diferente a cada PC cada vez que se reinicia (IP dinámica). Esto significa que si hoy la IP es 192.168.1.5, mañana podría ser 192.168.1.8 y el ERP perdería la conexión con la impresora.

Para fijar la IP y asegurar el correcto funcionamiento, tienes dos alternativas:

Opción A — Desde el Router (La más robusta y recomendada)

Consiste en dejar la configuración de red de la PC en "IP Automática" (DHCP) y reservar la IP desde la administración del router.

  • Ventaja: Si se corta la energía o se daña el internet de la tienda y necesitas compartir datos móviles desde un celular a la PC, la PC tendrá internet al instante porque su configuración de red sigue en modo "Automático". Cuando se vuelva a conectar al WiFi de la tienda, el router le volverá a entregar la misma IP asignada.
NOTA: El menú exacto cambia según la marca del router (TP-Link, ARRIS, Huawei, etc.), pero el procedimiento general es siempre el mismo. Abajo está el paso a paso documentado sobre un router ARRIS, a modo de ejemplo real.
Paso 1 — Identifica la puerta de enlace (la IP del router)

En la PC, abre CMD y ejecuta ipconfig. Busca el campo "Puerta de enlace predeterminada", esa es la IP del router (normalmente 192.168.0.1 o 192.168.1.1). No confundir con la IP de otros dispositivos de la red (cámaras, NVR, etc.) que también tienen su propia página de administración pero no son el router.

Paso 2 — Entra a la administración del router

Abre un navegador y entra a esa IP (ej: http://192.168.0.1). Inicia sesión con el usuario y contraseña del router (suelen venir en una etiqueta pegada al equipo).

Paso 3 — Ve a la sección LAN

Dentro del panel del router, busca la pestaña "LAN" (no "WAN", esa es la conexión hacia Internet del proveedor). Dentro de LAN, busca una sub-sección llamada "Lista de Clientes" (Client List).

Paso 4 — Encuentra la MAC de tu PC

En la tabla "Lista de clientes Attached", busca la fila que coincida con la IP actual de tu PC (la que viste en el ipconfig del Paso 1, ej: 192.168.0.30) y anota su Dirección MAC (ej: 44:FA:66:C4:62:B9).

Paso 5 — Crea la reserva DHCP

Sube hasta la sección "Lista de clientes con IP reservada" y haz clic en "Agregar". Llena:

  • Nombre: algo identificable, ej. PC-Impresora
  • Dirección MAC: la que anotaste en el Paso 4
  • Dirección IP: una IP alta y libre dentro del rango DHCP (ej: 192.168.0.201), para evitar que choque con otros dispositivos fijos de la red (cámaras, NVR, etc.)
Paso 6 — Aplica los cambios
WARNING: Después de hacer clic en "Agregar", la entrada queda en la tabla pero no se guarda de verdad hasta que hagas clic también en el botón "Aplicar" (separado del botón Agregar). Si no lo haces, el Status se queda en Offline y la reserva no surte efecto.
Paso 7 — Confirma el cambio en la PC

Reinicia la PC (o desactiva/activa el WiFi) para que tome la nueva IP. Luego corre ipconfig de nuevo y verifica que la "Dirección IPv4" ahora sea la IP fija que asignaste en el Paso 5.

Opción B — Desde la PC (Configuración en Windows)

Configura manualmente la IP fija directamente en la configuración de la tarjeta de red de Windows.

  • Cómo hacerlo:
    1. Ve a Configuración de red → Propiedades de tu adaptador WiFi/Ethernet → Protocolo de Internet versión 4 (TCP/IPv4) → Propiedades.
    2. Selecciona "Usar la siguiente dirección IP" y rellena los datos correspondientes.
  • Reglas muy importantes para evitar fallos con esta opción:
    • WARNING:
      > **Usa una IP alta para evitar conflictos:** Los routers asignan IPs automáticas bajas a los clientes que se conectan (ej: del `.2` al `.100`). Si dejas tu PC con una IP baja como la `.27` o `.28`, cuando la PC esté apagada el router podría darle esa misma IP al celular de un cliente. Al encender la PC habrá un conflicto de red. Elige una IP alta, como **`192.168.0.200`** o **`192.168.0.250`**.
    • IMPORTANT:
      > **Al compartir datos móviles:** Si compartes internet de un celular por WiFi a la PC, perderá la conexión porque el celular maneja un rango de red diferente. Deberás cambiar temporalmente la configuración de TCP/IPv4 de Windows a **"Obtener una dirección IP automáticamente"** para poder tener internet y navegar. Una vez regrese el WiFi de la tienda, deberás volver a escribir la IP fija asignada.

7.3 — Por qué el PHP en Hostinger NO funciona para esto

WARNING: El código PHP del ejemplo original que mandó Claude **NO funciona si lo ejecutas desde Hostinger**. El motivo es sencillo: Hostinger es un servidor en internet y las IPs locales como `192.168.1.X` son privadas, solo existen dentro de la red WiFi de la tienda. Hostinger no tiene forma de "alcanzar" esa IP.

El flujo que sí funciona es este:

Empleado abre el ERP en su navegador (mismo WiFi que la impresora)
    → Hace clic en "Imprimir"
    → JavaScript del navegador hace fetch a https://192.168.1.X:3000/imprimir
    → El servidor Node.js recibe la petición
    → La impresora imprime el ticket

La clave está en que el navegador del empleado SÍ está en la misma red que la impresora, aunque el ERP esté alojado en Hostinger. Entonces el fetch lo hace el navegador, no Hostinger.

7.4 — Código de integración con el ERP (JavaScript en el navegador)

Este es el fragmento JavaScript que debes agregar en el botón de imprimir del ERP. Funciona desde el navegador del empleado que está en la misma red que la impresora:

// Llama a esta función cuando el empleado haga clic en "Imprimir Ticket"
async function imprimirTicketERP(pedido) {
  // 1. Construir las líneas del ticket con los datos del pedido
  const lineas = [
    `Pedido #: ${pedido.codigo}`,
    `Fecha: ${pedido.fecha}`,
    `Sucursal: ${pedido.sucursal}`,
    `Atendido por: ${pedido.empleado}`,
    `--------------------------------`,
    ...pedido.productos.map(p => `${p.cantidad}x ${p.nombre.padEnd(15)} C$ ${p.precio}`),
    `--------------------------------`,
    `TOTAL:          C$ ${pedido.total}`,
  ];

  // 2. IP de la PC con la impresora en esta sucursal
  // Idealmente esta IP la guardas en la base de datos por sucursal
  const IP_IMPRESORA = '192.168.1.5'; // Cambiar por la IP real

  try {
    const respuesta = await fetch(`https://${IP_IMPRESORA}:3000/imprimir`, {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ lineas })
    });

    const resultado = await respuesta.json();

    if (resultado.ok) {
      console.log('Ticket impreso correctamente');
    } else {
      alert('Error al imprimir: ' + resultado.error);
    }
  } catch (err) {
    alert('No se pudo conectar con la impresora. ¿Está encendida la PC del servidor?');
    console.error(err);
  }
}

7.5 — Resumen del flujo completo de integración

[ERP en Hostinger]  ←→  [Navegador del Empleado en la Tienda]
                                        ↓
                         fetch('https://192.168.1.5:3000/imprimir')
                                        ↓
                         [PC de la Tienda — Node.js puerto 3000]
                                        ↓
                         [Impresora Epson TM-T20II conectada por USB]
TIP: Para manejar múltiples sucursales con impresoras en diferentes IPs, lo más ordenado es guardar la IP del servidor de impresión en la base de datos junto a cada sucursal, y que el PHP del ERP la pase como variable JavaScript al cargar la página. Así el mismo código funciona en todas las tiendas sin modificaciones.

PASO 8 — Solución de Problemas (Troubleshooting)

8.1 — Error "No se pudo conectar" o ERR_CONNECTION_REFUSED / ERR_CERT_AUTHORITY_INVALID

Este error ocurre principalmente en dos escenarios:

  1. Nueva PC o celular utilizado para imprimir:
    Cualquier dispositivo nuevo debe "aprobar" el certificado auto-firmado de la PC impresora antes de poder conectarse desde el ERP.

    • Solución: Abre el navegador en ese dispositivo, entra a https://<IP_DE_LA_PC>:3000/estado, haz clic en Configuración avanzada y selecciona Acceder/Continuar (no seguro).

  2. Cambio de dirección IP de la PC de la impresora:
    Si la IP fija de la PC cambió (por ejemplo, de 192.168.0.27 a 192.168.0.28), la aprobación del certificado hecha anteriormente deja de ser válida para el navegador.

    • Solución: Debes volver a entrar a la nueva dirección https://<NUEVA_IP>:3000/estado desde cada dispositivo y repetir el proceso de Configuración avanzada → Acceder/Continuar (no seguro). Además, asegúrate de actualizar la IP en la base de datos del ERP para esa sucursal.

8.2 — El servicio NSSM no inicia y se queda en SERVICE_PAUSED

Ocurre si el puerto 3000 ya está tomado por otro proceso de Node.js (por ejemplo, si tenías una ventana de CMD abierta corriendo node servidor.js de forma manual).

  • Solución:
    1. Cierra todas las consolas CMD de pruebas.
    2. Abre CMD como Administrador y cierra a la fuerza cualquier proceso fantasma corriendo:
      taskkill /F /IM node.exe
    3. Inicia o reinicia el servicio NSSM:
      C:\nssm.exe start ServidorImpresora

8.3 — Error de Spooler: "No se pudo enviar a la impresora"

Ocurre si el nombre compartido de la impresora en Windows no coincide con la constante NOMBRE_IMPRESORA definida en servidor.js.

  • Solución:
    1. Ve a Panel de Control → Dispositivos e Impresoras → Propiedades de Impresora → pestaña Compartir.
    2. Asegúrate de que el nombre del recurso compartido sea exactamente Impresora TM Tienda (o edita el código en servidor.js para que coincida).
